# GTA 6 Clipping Pipeline

An end to end, token minimal pipeline that turns livestreams and VODs into
vertical short form clips, built for the GTA 6 launch and usable for any
streamer content.

It finds the moments worth clipping two ways: a cheap audio and speech
analysis pass over recorded video, and a live chat spike detector that cuts
footage from *before* the chat explodes, because chat always reacts late.
Every clip comes out as a 1080x1920 MP4 with burned in captions, a hook line,
a persistent clickbait title, and a watermark, ready to post.

The default run uses **zero LLM tokens and no API keys**. Transcription is
local (faster-whisper), detection is counting statistics and heuristics, and
titles are generated by rules from the clip's own transcript.

## What it does

**VOD mode** (`src/pipeline.py`)

1. Ingest a local file, a direct URL, or a page URL via yt-dlp
2. Cheap gate: per second audio energy (numpy), so silent stretches never
   reach the transcription model
3. Local transcription of the gated windows only (faster-whisper)
4. Heuristic highlight ranking: hook words, questions, numbers, speech
   density and model confidence pick the top windows, snapped to sentence
   boundaries
5. Render: cut, reframe to 1080x1920 (blurred fill `fit` layout, or `crop`),
   burn in phrase captions, a hook line, a rule based clickbait title, and a
   watermark

**Live monitor mode** (`src/monitor.py`)

Chat is bucketed into 1 second counts against a trailing 120 second
baseline. A trigger must clear all three bars at once:

- rate at least 3x the baseline mean (configurable)
- rate at least mean + 6 standard deviations
- an absolute floor of 5 messages per second

When it fires, the clip window starts **20 seconds before the trigger**
(chat lags the stream, so the moment already happened) and runs 10 seconds
past it. One clip per event, with a cooldown.

**YouTube live tools**

- `src/youtube_chat.py` captures YouTube Live Chat over plain HTTPS
  (innertube polling, no API key) and writes the monitor's JSONL format
- `src/youtube_dvr_grab.py` records a window from a live stream's HLS DVR
  buffer instead of the live edge, which is far more reliable through
  proxies and rate limits

Twitch capture works with streamlink plus the VOD mode, as in the examples
below.

## Quick start

Requirements: Python 3.10+, `ffmpeg` on your PATH.

```bash
git clone https://github.com/HussainHacks/gta6-clipping-pipeline.git
cd gta6-clipping-pipeline
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

Clip a recorded video or VOD:

```bash
.venv/bin/python src/pipeline.py --input stream.mp4 --clips 3 --streamer "Kai Cenat"
```

Clips land in `clips/` with a `clips-manifest.json` describing each one
(source window, score, title).

## Usage

### VOD mode

```bash
.venv/bin/python src/pipeline.py --input <file-or-url> [options]
```

| Flag | Default | Meaning |
| --- | --- | --- |
| `--clips` | 3 | How many clips to render |
| `--layout` | `fit` | `fit` keeps the whole 16:9 frame inside blurred fill, `crop` fills the frame |
| `--streamer` | none | Streamer name used in clickbait titles |
| `--no-gate` | off | Skip the audio energy gate and transcribe everything |
| `--no-watermark` | off | Render without the watermark |
| `--no-clickbait` | off | Render without the clickbait title |
| `--out-dir` | `clips/` | Output directory |

### Live monitor (offline scan of a chat log)

```bash
.venv/bin/python src/monitor.py --chat-log chat.jsonl
```

Chat log format is JSON Lines, one message per line
(`{"ts": 1712345678.0, "user": "name", "text": "LETS GOOO"}`); a CSV
variant `ts,user,text` also works. Flags: `--pre-roll` (default 20),
`--post-roll` (10), `--spike-ratio` (3.0), `--buffer` (60).

### YouTube live chat capture

```bash
.venv/bin/python src/youtube_chat.py --url <watch-url> --duration 600 --out chat.jsonl
```

### YouTube DVR capture

```bash
.venv/bin/python src/youtube_dvr_grab.py --video <video-id> --seconds 620 --out capture.ts
.venv/bin/python src/pipeline.py --input capture.ts --streamer "Kai Cenat"
```

### Twitch capture (via streamlink)

```bash
streamlink twitch.tv/<channel> 480p -o capture.ts
.venv/bin/python src/pipeline.py --input capture.ts --streamer "<Channel>"
```

## Configuration

Set these as environment variables:

| Variable | Default | Meaning |
| --- | --- | --- |
| `WATERMARK_TEXT` | `@yourchannel` | Watermark burned into every clip |
| `WATERMARK` | `1` | Set to `0` to disable the watermark |
| `CLICKBAIT` | `1` | Set to `0` to disable clickbait titles |
| `STREAMER_NAME` | none | Fallback streamer name for titles |
| `WHISPER_MODEL` | `tiny` | faster-whisper model size; `small` is noticeably better on fast or shouted speech |

## Project layout

```
src/
  pipeline.py        VOD mode: ingest, gate, transcribe, rank, render
  monitor.py         Live chat spike detection with pre roll buffer
  youtube_chat.py    YouTube Live Chat capture over HTTPS
  youtube_dvr_grab.py  YouTube live DVR window recorder
tests/
  test_monitor.py    Synthetic chat spike test (300 s of chat, one spike)
```

Run the test:

```bash
.venv/bin/python tests/test_monitor.py
```

## Token budget

The default pipeline spends no LLM tokens at any stage. The only optional
spend is a future LLM re rank or title pass over the top 3 to 5 candidates
only (roughly 1,000 to 2,500 tokens per source video), and it is off by
default and not required.

## Known limitations

- The `tiny` Whisper model garbles some words on fast or shouted speech.
  Use `WHISPER_MODEL=small` on a machine with a GPU for the quality path.
- The audio gate earns its keep on sparse audio; on narration dense
  content it passes almost everything, and chat is the primary gate in
  live mode.
- Reframing is center based with no face tracking, so a facecam stays
  small in the `fit` layout.
- 480p sources upscale to 1080x1920 and will look soft.

## Rights note

Clipping other people's streams is a rights and platform rules question.
Clip your own content, or content you have permission to use, and check
the game publisher's footage policy. For GTA 6, gameplay plus streamer
reaction is the accepted pattern; bare cutscenes and ending footage are
what get taken down. This pipeline publishes nothing by itself.
